# 背包与道具系统（需求文档）

> 状态：✅ **背包 + 道具 + 余额优化已全部上线（2026-09-28 晚）**，实测通过。
> 机制对照 docs/01：乐趣核心 = 攒箱子的期待感（变率奖励） + 自选开箱时机的仪式感 + 道具的策略性。

## 一、背包系统（宝箱改造）✅ 已拍板

### 现状 vs 目标

| 环节 | 现状 | 目标 |
| --- | --- | --- |
| 掉落 | 完成任务 → 按掉率判定 → **立即自动开箱**积分入账 | 完成任务 → 按掉率判定 → 宝箱**进背包**（未开启） |
| 入账 | 开箱即入账 | **用户开箱时才入账**（积分流水记在开箱时刻） |
| 查看 | 无箱体概念 | 背包页按类型聚合显示未开宝箱（签到宝箱 ×3 …） |
| 开箱 | 自动 | 用户自选时机手动开（单开 / 全部开启） |

### 已拍板规则（2026-09-28）

| # | 问题 | 结论 |
| --- | --- | --- |
| 1 | 延迟开启 vs 即时铁律 | **A：接受攒箱期待感**，掉落不入账，开箱才入账 |
| 2 | 过期机制 | 无期限，永久存放 |
| 3 | 「全部开启」 | 要，逐个弹出庆祝 |
| 4 | 开箱积分区间 | 维持各宝箱类型 min~max 配置不变 |
| 5 | 未开箱总数提醒 | 要（我的页角标 / 背包入口数字） |
| 6 | 撤回连带收回 | **要**：撤回任务完成行时，该次掉落进背包的未开宝箱一并收回 |

### 实现要点

1. 新表 `backpack_items`：id / kind（box）/ type_id（关联宝箱类型）/ source（来源任务完成行的流水 id，用于撤回连带收回）/ created_at / opened_at / status（unopened/opened）
2. 掉落 = 写一条 backpack_items（unopened），不写积分流水；开箱 = status→opened + 写 box 积分流水
3. 任务完成动效：有掉落 → 「🎁 获得 宝箱 ×1」；无掉落 → 「+N 积分到账」
4. 撤回任务完成行 → 按 source 找到该次掉落的 unopened 宝箱 → 删除（收回）
5. 入口：「我的」页「背包」卡片（带未开数量角标）→ 独立子页面（带返回），底部 4 Tab 不动

## 二、道具系统（初步定义，还剩 5 问）

### 道具清单（用户提出）

| 道具 | 效果（已定） | 备注 |
| --- | --- | --- |
| **积分利息卡** | 使用后获得「当前积分 × 3%」的积分（向下取整），一次性 | 基数=使用那一刻的积分余额 |
| **余额利息卡** | 使用后获得「当前余额 × 3%」的现金（取整到分 ¥0.01），一次性 | 基数=使用那一刻的现金余额 |
| **冷却重置卡** | 选择一个**冷却中**的商城商品，清零其冷却（LastRedeemedAt 置空），立即可再兑 | 只列出冷却中的商品，无冷却商品不可选 |

### 已拍板（2026-09-28 晚）

| # | 问题 | 结论 |
| --- | --- | --- |
| 1 | 生效时机 | **A：使用即结算**，snapshot 3% 立刻到账 |
| 2 | 限次 | **不限**，攒多少用多少，观察经济再说 |
| 3 | 来源 | **宝箱开出**，不走商城购买（商城购买是后期可选）；定价问题随之消失 |
| 4 | 背包布局 | 无 Tab，宝箱区/道具区上下两个区块，各自 **6×2 网格**（两行六列，超出一律换行续排） |

### 第二批道具（2026-09-30 拍板，✅ 已上线）

| 道具 | type_id | 效果（已定） | 关键规则 |
| --- | --- | --- | --- |
| **免罚金牌** | 4 | 挂上后 **24 小时内**，打开 App 时触发的所有补罚全免（昨日 daily、上周 weekly、逾期 once） | **预防性道具**：结算挂在 ListTasks 上（打开 App 瞬间触发），已结算的罚分不返还；豁免时幂等标记照写（LastPenaltyKey/PenaltySettled），本周期不再重罚；使用行写 0 分审计流水，返回当天已结算笔数供前端提示 |
| **幸运符** | 5 | 下一个开启的宝箱积分 ×2 | 只作用于批量开启的**第一个积分箱**；开出道具**不消耗**；可与运势卡叠加 |
| **双倍卡** | 6 | 下一个完成的任务积分 ×2 | 多张排队：连续完成任务逐张消耗；宝箱照常掉落不受影响；完成动效显示"⚡双倍卡生效"金色数字 |
| **运势卡** | 7 | 下一个开启的宝箱**上限、下限都 ×2**（如 10~100 → 20~200） | 同幸运符只吃第一个积分箱；与幸运符叠加 = 区间×2 后再整体翻倍（等效 ×4） |

**实现基建**：新表 `pending_effects`（id / kind / expires_at / created_at），kind = `double_task` / `lucky_box` / `boost_box` / `exempt_penalty`；前三种无过期、触发即消耗，exempt 用 expires_at 做 24h 窗口。消耗统一"事务内先删（RowsAffected 防双耗）后生效"，生效写进流水 note（如「宝箱开出（幸运符×2）」「完成任务（双倍卡×2）」）。

**存量修复（随本批）**：任务完成时的道具掉落判定原走旧三列（ItemRatePoints/Cash/Reset），与开箱的 ItemDrops 累积概率落点不一致——已统一为 ItemDrops，新道具才可能从任务掉落；qty>1 时逐条进背包。

### 还剩 5 问（拍板后道具可开工）

| # | 问题 | 选项 | 我的倾向 |
| --- | --- | --- | --- |
| 1 | **开箱产出规则**（道具从箱子开出后的核心问题）：开出道具的箱子还给不给积分 | A 本箱产出二选一：按道具概率命中→出道具、未命中→给积分 min~max B 积分照给，道具是额外 bonus | A——道具就是本箱产出，经济最可控；B 等于箱子必得积分+白送道具，积分通胀 |
| 2 | 道具概率怎么配 | 每个宝箱类型加一个「道具概率 %」字段（默认 0=纯积分箱），命中后三种道具**等概率**出一种；每道具独立概率太复杂 | 同左 |
| 3 | 道具使用的流水与撤回 | 利息卡入账行当天可撤（退积分，**卡不还**，已消耗）；重置卡写一条 0 分审计行（note 记录重置了哪个商品），可撤但撤了冷却**不恢复** | 同左，统一"所有道具使用有迹可循" |
| 4 | 0 基数保护 | 积分/余额为 0 时用利息卡 = 得 0，白费一张卡——使用弹窗需提示「当前利息为 0，确认使用？」防误触 | 加提示 |
| 5 | 背包格子内容 | 每格=图标+名称+×N 角标，点按弹操作层（开箱/使用/全部开启） | 同左 |

### 通用规则（草案）

1. 道具与宝箱同在背包页：宝箱区、道具区上下两个区块，各自 6×2 网格，同类堆叠 ×N
2. 道具来源：**宝箱开出**（商城购买留作后期可选）
3. 使用即写流水（type=item），审计可查
4. **道具产出的流水行不可撤回**（用户拍板：利息卡入账行不能撤），但记录完整；撤回任务完成行时，该次掉落进背包的未开宝箱/道具一并收回

## 三、我的页：余额记录展示优化 ✅ 已拍板

1. 余额卡内兑换/消费记录**最多展示 5 条**
2. 「更多」→ 独立子页面（带返回）
3. 明细页对齐统计页规格：**今天 / 昨天 / 近7天 / 近30天 / 自定义（起止日期）** chips
4. 顶部汇总：**获取 / 消耗**——消耗红色加粗做视觉重点
5. 类型筛选 chips（全部 / 兑换 / 消费）：要
6. 不做分页，日期筛选足够

### ⚠️ 道具同步铁律（2026-09-30 拍板；同日升级为注册表架构）

**道具池单一事实来源 = 后端 `backend/internal/api/itemdef.go` 注册表**（定义：id / 名称 / 图标 / 图鉴文案 / 交互模式 use_mode / pending 元数据；使用逻辑：`itemUses` handler map）。图鉴页、背包道具格、宝箱掉落配置 picker、掉落校验全部由 `GET /api/items/guide` 与注册表驱动。

**新增 / 修改 / 下线道具的改动面**：

| 变更类型 | 必改 | 前端 |
| --- | --- | --- |
| 新增 confirm 型道具（挂 pending / 直接结算） | `itemdef.go` 注册行 + use handler（触发型直接用 `armPending` 工厂一行注册）+ docs/05 本表 | **零改动**（自动出现在图鉴/背包/掉落配置） |
| 新增特殊交互模式道具 | 同上 + 前端按 `use_mode` 加一个分支 | 一处分支 |
| 修改效果/文案 | `itemdef.go` + docs/05 | 零改动 |

生效站点（`OpenBoxes` / `CompleteTask` / `SettlePenalties`）引用 `itemdef.go` 的 pending kind 常量，新增"下一发 XX"型道具时在对应站点补生效逻辑即可，定义不用重复。

改完必须重新走构建链（npm build → 拷 dist → go build）并**重启 server.exe**（前端 embed 在二进制里，不重启永远是旧页面——2026-09-30 图鉴过期事故教训）。

## 六、宝箱道具掉落动态配置（✅ 已上线，2026-09-30）

> 背景：旧设计是宝箱上三个写死的概率列（利息卡积分%/利息卡余额%/重置卡%），且读码发现**开箱逻辑里从未实现道具掉落判定**——概率列从未生效。本节重构一并修复。

| 项 | 方案 |
| --- | --- |
| 表单 | 「道具掉落」动态列表：每行 = 道具下拉 + 概率% + 数量 + 删除；「+ 添加」增行（≤3 行）；实时显示「剩余 X% 开积分 min~max」 |
| 校验 | 概率 0-100、数量 1-99、同道具不重复、概率和 ≤ 100（剩余=积分概率） |
| 数量语义 | 概率管「开到/开不到」；开到时**一次进背包 qty 张** |
| 存储 | Box.ItemDrops JSON 列（gorm serializer），旧三列标废弃保留兼容；启动时一次性迁移（旧三列 >0 转 JSON，0% 不迁） |
| 开箱 | 掷 0~99 → 累积概率落点判定道具 → 进背包 qty 张；未落上 → 开积分 min~max |
| 结果展示 | 开箱结果弹层兼容道具：「🪙 积分利息卡 ×2」；纯积分时显示「共 +X 积分」 |
