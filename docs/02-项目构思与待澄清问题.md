# SelfBet 项目构思与待澄清问题

> 项目一句话：**一个用来记录"自己让自己上瘾"的系统 —— 用游戏的机制让学习像打游戏一样上瘾。**
> 当前阶段：**规划阶段。用户未宣布开始编码前，绝不写任何代码。**

## 一、初步构思（用户原话整理，2026-09-27）

1. 设定一些任务
2. 完成任务 → 获得积分或货币
3. 积分/货币 → 在商城兑换一些东西

后期肯定需要补充。**核心机制见《01-游戏化机制素材库》——01 是让学习上瘾的核心引擎，先读 01 再读 02。**

## 二、构思与视频机制的对应假设（待确认）

| 视频机制 | 本项目的对应物 |
| --- | --- |
| 拆小怪（目标拆小） | 任务的粒度设计 |
| 物理多巴胺（即时奖励） | 完成任务 → 积分/货币**秒到账** + 到账动效 |
| 实体化进度条（玻璃罐/纸摞） | 等级 / 进度条 / 累计统计可视化 |
| 及时正反馈 | 任务 → 奖励闭环零延迟 |

## 三、方法论：建议采用 spec 驱动（轻量版）

**结论：适合，但要轻。** 理由：

1. 需求注定滚动增长（后期肯定补充），spec 是需求的锚，防止改着改着跑偏
2. 数据模型（任务/积分/商城/兑换记录）是"改起来最贵的部分"，先用 spec 定死比先写代码划算
3. 本项目的特殊性：**积分经济系统本身就是游戏策划问题**（怎么挣、怎么花、防通胀），必须在 spec 阶段想清楚，代码实现反而是次要的

建议的轻量 spec 结构（开始编码前完成，个人项目三文件封顶）：

- `docs/spec/requirements.md` —— 用户故事 + 验收标准
- `docs/spec/design.md` —— 数据模型、页面结构、接口、技术选型
- `docs/spec/economy.md` —— 积分经济规则（挣/花/通胀/防作弊）—— 本项目最特殊的一篇
